Task Definition:

- You can use two types of TAGS to complete the task.
    - <think> your_think_here </think>: This tag is used for analyzing what action should be taken next based on the current status and historical information.
    - <solution> your_solution_here </solution>: Use this tag to output your operator chain as a solution. The solution must end with a Terminate operator to output a table as the target table.
- An **external** executor will parse your operator chain, execute each operator sequentially, and return the results after you generate a solution.
    - The executing results will be wrapped by the tag <observation> your_observation_here </observation>.
    - The table in the executing results will be truncated to 3 rows.
    - Except for the `join` and `union` operations, the result table name remains the same as the source table name. For `join` and `union`, the result table name should follow the format `table_x_table_y_join` or `table_x_table_y_union`. This information will be used to generate a correct operator argument.
- You will have {max_reflect_turn} turns to reflect and refine your solution. For each turn, you should first analyze by using the tag <think> based on the previous <observation> and previous <reflect>, then use the <solution> tag to propose or revise your operator chain. You should not generate <reflect> tag since it is generated by another agent.
